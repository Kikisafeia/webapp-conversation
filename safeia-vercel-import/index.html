Aclaración del documento base

Las fuentes técnicas del documento se enfocan en Harness Engineering, agentes de IA, desarrollo asistido por software y DevOps. El propio documento indica que no contienen normativa SST ni legislación chilena aplicable.

Fuentes oficiales que el documento recomienda incorporar

  • Ley N° 16.744.
  • Decreto Supremo N° 40.
  • Decreto Supremo N° 594.
  • Compendios de SUSESO y manuales técnicos de organismos administradores.

Regla para la presentación

Roles APR, nivel de riesgo, criterios preventivos, obligaciones legales y cualquier decisión de cumplimiento se presentan como puntos que deben ser validados por un profesional competente y las fuentes oficiales correspondientes.

Prompt estructural

Agente de programación · AGENTS.md + ciclo PEV

Actúa como un Staff Software Engineer especializado en desarrollo asistido por IA y aplicaciones web modernas.

Quiero construir la primera versión (MVP) de una WebApp de Seguridad y Salud en el Trabajo (SST) para el reporte y cierre de condiciones inseguras.

Antes de escribir código, debes seguir estrictamente este protocolo operativo:

1. Lee y asimila las directrices de nuestro repositorio en AGENTS.md.
2. Aplica el Bucle PEV (Planificar-Ejecutar-Verificar):

FASE PLAN
Analiza los requisitos del MVP: formulario con foto Antes, lista de hallazgos por estado, asignación de responsable y carga de evidencia foto Después para cierre. Genera una propuesta de diseño técnico en .harness/plan.md indicando arquitectura (Next.js/React, Tailwind CSS, TypeScript), esquema de base de datos y componentes UI mobile-first. Detente y solicita mi aprobación explícita antes de modificar o crear archivos.

FASE EXECUTE
Implementa los componentes mediante cambios quirúrgicos mínimos. Asegúrate de que las llamadas a APIs de visión o almacenamiento de imágenes estén aisladas en endpoints seguros del backend.

FASE VERIFY
Ejecuta npm run build y npm run lint. No des la tarea por completada sin aportar evidencia de que el código compila sin errores y pasa los linters.

LÍMITES ESTRICTOS
- Nunca expongas claves de API o credenciales en el frontend.
- Nunca uses bypass o eslint-disable-next-line para ignorar errores del compilador o linter.
- Nunca realices refactorizaciones no solicitadas fuera del alcance del plan.

Responde primero únicamente con el PLAN estructurado para revisión.
